# 源码整理与发布范围

项目按源码仓库发布。提交前检查以下范围，避免把本机模型、歌曲、结果或凭据放进 Git 历史。

## 源码候选

保留应用 `timing/`、静态网页 `web/`、公开维护脚本、测试、空读音模板、启动 / 安装脚本、`pyproject.toml` / `uv.lock` 和项目文档。公开 `scripts/` 用 Git 白名单明确保留安装器、依赖清单、GPU 检查和源码检查；新增维护脚本需同时更新 `.gitignore`。本次白名单移除了旧 `download_lead.py`；`download_separator.py` 与其余安装器保留。

本机的模型、音频、任务导出、虚拟环境、解释器副本、pytest 临时文件、编译缓存、规划记录、设计 QA 和研究历史被忽略。旧模型代码、单歌修复和历史试验脚本已从应用目录删除，源码备份保存在 `.runtime/refactor61/before/`，同样被忽略。原有歌曲和任务结果保留。

不要直接上传整个文件夹 / 手工 ZIP：这类操作不遵守 `.gitignore`。若后续需要打包，只使用已经检查过的源码清单。模型和歌曲无需为源码发布而删除。

## 只读检查

```powershell
git status --short --untracked-files=all
.\.venv\Scripts\python.exe -X utf8 scripts/check_publication.py
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
node --test tests/test_web_ui.cjs
```

检查器用 Git 枚举“已跟踪 + 未忽略”的候选，检查运行目录、大文件、媒体 / 权重 / 压缩包、密钥文件和常见凭据格式。只报告路径 / 行号 / 规则，不回显值、不修改 Git 或文件，不联网。它不能取代人工内容和历史审查，也不能判断所有自定义密钥和歌词来源。

`.gitignore` 不会移除已经跟踪的文件；因此检查器也扫描已跟踪候选。如果将来曾经误提交密钥或音频，需要另外处理已提交历史。首次提交只包含检查过的源码清单。

## 验证的范围

源码 checkout 为当前支持的安装方式，尚未发布 PyPI / 独立 wheel 或容器。开发者可用 `uv sync --frozen` 安装含 pytest 的开发依赖；`setup.ps1` 用 `--no-dev` 安装运行环境。Node 只执行无第三方依赖的页面逻辑测试。

模型 revision / 哈希、依赖锁和本机 GPU 验证不等于所有平台均可复现，也不代表实际歌曲边界已通过精度验收。依赖已下载词典、运行库或权重的测试在干净源码环境明确跳过。
